# Contributing

Thanks for improving `white-label-model`.

## Setup and checks

Use Node.js `^22.18.0 || >=24.11.0` and npm. From the repository root:

```sh
npm ci --ignore-scripts
npm run build && node --test test/<file>.test.js   # quick loop while iterating
npm run lint && npm run coverage && npm run audit  # full gate before opening a PR
```

`npm run coverage` builds (which typechecks), runs the consumer type checks and every Node test, and requires 100% statements, branches, functions, and lines per source file. Lint warnings fail the gate; `npm run lint` covers `src/`, `test/`, and `benchmark/`. `npm run benchmark` prints timings if your change affects performance.

Two further checks run in CI and can be run locally:

- `npm run build && npm run test:browser` bundles the built package with esbuild and runs `test/browser/` in real Chromium through Playwright. It is not part of `npm test` or `npm run coverage`. Install a browser once with `npx playwright install chromium`, or point `PLAYWRIGHT_CHROMIUM_EXECUTABLE` at an existing Chromium binary.
- `npm run bench:ci` runs a reduced `benchmark/model.bench.js` and fails if any operation is more than 3x slower than `benchmark/baseline.json` or an event counter changes. After an intentional performance change, refresh the baseline on a quiet machine with `node --run build && node benchmark/model.bench.js --ci --update-baseline` and commit the new `benchmark/baseline.json`.

`dist/` is generated by the build and ignored by git; never commit it.

## Pull requests

- Keep changes focused and preserve the documented Model contract for object, array, and Map roots.
- Keep deep observation lazy and path-based. Do not add whole-model scans, deep diffs, or compatibility aliases without an explicit architectural decision.
- Edit `src/`, not `dist/`.
- Add or update tests when behavior changes. Do not weaken coverage, lint, type, or security checks.
- Review the complete diff for credentials, private data, debugging code, and unrelated formatting.
- Breaking public API changes need a SemVer major release, not compatibility shims.

## Security

The optional validator receives the complete proposed state before construction or an explicit mutation is committed; returning `false` rejects it. Use it for untrusted runtime data such as API, storage, or user input. Direct nested writes through `get()` do not run it. Never put real secrets or personal data in tests or docs, and report suspected vulnerabilities as described in [`SECURITY.md`](SECURITY.md).
